# Signal Flattening Root Cause Report

## Overview
A deep trace was executed on the signal generation lifecycle for `GBPUSD` and `USDCHF` using the new `--signal-trace` diagnostic mode. Both assets generated strong baseline candidates (Signal Score: 80.0, Gate: PASSED), successfully bypassing the regime filter and standard indicator checks. However, their signals were flattened before reaching the Risk Gateway.

## Root Cause Findings

1. **Exact File and Line Causing Flattening**
   - **File:** `src/ml/xgb_filter.py`
   - **Function:** `apply_ml_gatekeeper()`
   - **Line:** ~122-127

2. **Exact Condition Causing Flattening**
   The codebase caught a `RuntimeError` when attempting to run the ML filter because the **`xgboost` Python library is not installed in the system environment**.
   - `predict_quality()` detects `XGB_AVAILABLE = False` and raises: `ML model failed to load: XGBoost library not available`
   - The global `try/except` block in `apply_ml_gatekeeper` catches this error.
   - It appends `ML_gatekeeper_block` to the blocked reasons and explicitly sets `dec.direction = "flat"`.

3. **Intentional Safety Behavior vs. Bug**
   This is **intentional and correct safety behavior**. The system is designed to "fail-closed." If the ML Trade Filter is enabled in the configuration but cannot execute (due to missing dependencies, missing model files, or corrupted data), it explicitly blocks all trades rather than allowing unverified signals to pass through. The underlying "bug" is simply a missing environment dependency (`xgboost`).

4. **Should GBPUSD and USDCHF Have Reached the Risk Engine?**
   **YES.** Both assets scored 80.0/72 and passed all technical gates. Had `xgboost` been installed, and assuming the XGBoost model predicted a quality score above the `0.55` block threshold, these signals would have been handed directly to the Risk Engine as active candidates.

## Resolution

5. **Recommended Safe Fix**
   The fix does not require altering any logic. Simply install the missing dependency in your active Python environment:
   ```bash
   pip install xgboost
   ```

6. **Tests Added**
   - Modified `diagnostic_run.py` to include a robust `--signal-trace <SYMBOL>` flag.
   - The trace mocks the exact live data feature row, evaluates the strategy, explicitly dumps the boolean result of every technical gate (Regime, Session, RSI, ADX, ATR, Alignment), and exposes the internal ML decision state and handoff status to the Risk Engine.

7. **Can the Demo Realtime Test Continue?**
   **YES**, but only after running `pip install xgboost`. Once installed, the ML filter will operate properly, and high-quality signals like the ones generated by GBPUSD/USDCHF will flow naturally into the Risk Engine and execute on the demo account.
